# 15 — Scanned-PDF chain: text layer, then Tesseract, then a vision fallback

**Source:** [15-ocr-chain.md](../../tickets/15-ocr-chain.md)
**Type:** AFK
**Blocked by:** 05 (the vision fallback reuses the extractor)
**Wave:** 5
**Lane:** ocr
**Verifier profile:** full (untrusted parser)
**What it delivers:** PDFs without a text layer are rendered with pypdfium2, OCR'd with Tesseract when the binary exists, and otherwise (or below the confidence floor) sent to the vision model through BinaryContent.

## Context
- Why: D16 ('3 then 1': local first, model last).
- Constraining decisions: D16. Tesseract is not installed (verified 2026-11-12); this ticket must work and be tested without it. Tesseract-path tests are `skipif(no binary)`, and the vision path is tested offline with a scripted FunctionModel that asserts it received an image part. Live vision verification is ticket 18.
- Failure paths: No binary → a `ocr_skipped` trace line, then vision. An empty OCR result or mean confidence < 60 → vision. Vision unavailable offline with no golden → LOAD_FAILED, never a crash.
- Plan anchors: PRD FR-1.2; D16

## Acceptance criteria
- [ ] Rasterised 1011 (data/invoices/scans/invoice_1011_scan.pdf, generated by a committed script; kept out of the adversarial set) has no text layer
- [ ] Without tesseract: the chain logs the skip and the scripted vision model receives an image
- [ ] With tesseract (skipif): the OCR text contains INV-1011
- [ ] The offline golden for the scan equals the 1011 PDF golden (not the TXT one, which has more fields)
